# 岩崎さんへ — 「段取り名人」iOSアプリ ビルド・申請手順

岩崎さん

毎日1問の段取りパズル「段取り名人」の iOS プロジェクトです。
料理や工事の作業カードを、手・コンロ・炊飯器・クレーンなどの空き具合を読みながら並べ、全部が終わる時刻を最短にするパズルです。
**Xcode で開いてビルド → App Store 申請** まで進められる状態にしてあります。

必要な作業は大きく2つです。

1. Xcode で開き、署名（Team）を自社アカウントに設定してビルド → 3章・4章
2. App Store Connect にアップロードして審査に提出 → 5章

申請時に入力するアプリ名・説明文・キーワードなどは、6章に**下書きを用意してあります**。
そのまま使っていただいても、修正いただいても構いません。

**申請の前に、清武が決めてお知らせすること**（決まるまでは申請を止めてください）:

- 岩崎さんの Mac の macOS で、どの Xcode を使うか（2章の表。macOS 27 の Mac なら、清武が先に対応します）
- 審査のガイドライン 1.5 のための、問い合わせ用のメールアドレス（6章「サポート URL」）。いまのサポートページの連絡先は GitHub の Issues だけです
- 5章の「EU の取引業者（trader）の申告」と「App Review の連絡先」に入れる会社の情報・担当者（嘘つき村の事件簿で済ませていれば、同じアカウントでは申告は1回だけです）

ご不明な点があればお知らせください。（清武）

## 1. アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | 段取り名人（ホーム画面の表示も「段取り名人」） |
| Bundle ID | `work.ltv.dandori` |

### 遊び方（審査・動作確認用）

- 作業カード（「米を研ぐ 3分【手】」「ご飯を炊く 25分【炊飯器】」など）を、タップした順に工程表へ置いていく
- 作業は「前の作業が終わり」「使う道具（手・コンロ・炊飯器・職人・クレーンなど）が空いた」ときに始まる。同じ道具は一度に1つだけ。全部置いたときに全部が終わる時刻（完成）を、最短にする
- カードには「いま置くと◯〜◯分」が出る。置き間違えたら［1つ戻す］。最短なら★3、最短の1割の遅れまでなら★2。何度でもやり直せる
- 結果の画面では「ここがコツ」と、［最短の段取りを見る］で最短の一例を1枚ずつ再生できる（あなたの並べ方と何枚目で分かれたかも出る）
- 毎日1問の「今日の段取り」（全員同じ問題）は曜日で難しさと題材が変わる（月・火は★1。台所の日は単位が「分」、現場（工事）の日は「日」）。練習（★1〜★3・台所／現場）は何問でも遊べる。過去の日は「記録帳」から遊べる
- 初めて開くと、ホームに「はじめての方へ」が出る。［第1話を始める］で案内つきの3問「はじめての段取り」（各1分。記録には数えない）。審査で遊び方を見せたいときはここから
- 問題はすべてアプリの中でその場で作り、全部の並べ方を試して本当の最短を確かめてから出している

## 3. ビルド手順

ターミナルで、このフォルダ（Dropbox の `アプリ開発/思考力/段取り名人/ios-app`）に移動して、以下を順に実行してください。
（`cd ` と打ってから、Finder でこのフォルダをターミナルにドラッグすると場所が入ります）

```bash
# 0) 日本語のパスで CocoaPods が止まらないように（ターミナルを開くたびに1回）
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8

# 1) 依存パッケージを取得（初回のみ。数十秒）
npm install

# 2) アプリ本体（../index.html）を iOS 側へ反映し、pod install まで行う
npm run sync

# 3) Xcode で開く
open ios/App/App.xcworkspace
```

> **注意**: 必ず `App.xcworkspace` を開いてください（`App.xcodeproj` ではありません）。
> 手順2で `✔ Updating iOS native dependencies with pod install` と出れば成功です。
> この Mac（清武の作業用）には Xcode が無いため、ビルドの確認は GitHub のクラウド Mac（GitHub Actions の「iOS build check」）で行っています。

### `npm run sync` でエラーが出たら

| 表示されるエラー | 対処 |
|---|---|
| `pod: command not found` | `brew install cocoapods` を実行してから、もう一度 `npm run sync` |
| `Unicode Normalization not appropriate for ASCII-8BIT` | 手順0の `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` を実行してから、もう一度 |
| `xcodebuild requires Xcode, but active developer directory ... CommandLineTools` | Xcode を一度起動して初期設定を済ませ、`sudo xcode-select -s /Applications/Xcode.app` を実行してから、もう一度（Xcode 26 の名前を変えて置いた場合は、その名前の .app を指定） |
| `CocoaPods could not find compatible versions` | `cd ios/App && pod repo update && pod install && cd ../..` を実行 |
| `npm ERR!` で始まるもの | `rm -rf node_modules && npm install` をやり直す |

それでも通らない場合は清武までご連絡ください。エラー文をそのまま貼っていただければ対応します。

### 動作確認

上部のデバイス選択から実機またはシミュレータ（iPhone）を選び ▶ で起動します。確認ポイント:

- 起動画面にアプリのアイコン（藍の方眼紙に付箋の帯）が出て、ホーム（今日の段取りのカード）に切り替わる。端末がダークのときは起動画面も紺になる
- ホームの［今日の段取りを始める］→ 最初に「最短は何分？」の予想（飛ばせる）→ 作業カードを押すと工程表に帯が入り、軽く震える。前の作業がまだのカード（鍵の印）を押すと短く震えて「先に〇〇を置いてください」と出る（振動は実機のみ）
- 全部置くと「完成」（最短なら「最短！」と紙吹雪）が出て、少しあとに結果の画面へ。完成で震える
- 結果の［最短の段取りを見る］で、最短の一例が1枚ずつ再生される
- 設定 →「毎朝の通知」を ON にすると通知の許可を求められる。許可すると「知らせる時刻」が選べる（その時刻に「今日の段取りが届きました」が届く。通知を押すと今日の段取りが開く）
- 設定の「画面の色」を「ダーク」「ライト」に切り替えると、画面上端の時計・電池の文字色もそれに合わせて変わる（端末の外観と逆にしても読める）
- ホームの「はじめての方へ」→［第1話を始める］で、はじめての段取りの第1話が開き、上の案内の付箋がカードを置くたびに変わる
- 練習の ★3（台所・現場を切り替えられる）で、コンロや職人が2つある、または2つの道具を同時に使う作業がある問題が開く（作るのに一瞬「段取り表を用意しています…」が出る）
- アプリを完全に終了して開き直しても、完成の記録・連続日数が残っている
- 機内モードでも起動して遊べる（書体だけ端末のゴシックになる）
- 設定のいちばん下の「サポート・プライバシーポリシー」で、サポートページ（GitHub Pages）が開く

## 4. Xcode 上での署名設定

1. 左のファイル一覧で一番上の **App**（青いアイコン）を選択 → TARGETS の **App** → **Signing & Capabilities** タブ
2. **Team** に自社の Apple Developer アカウントを選択（**Automatically manage signing** は ON のまま）
3. **Bundle Identifier** は `work.ltv.dandori`（自社で別の ID にする場合はここを変更）
4. **General** タブで **Version**（例: `1.0.0`）と **Build**（例: `1`）を設定。再提出のたびに Build を1つ上げる
5. Capability の追加は不要です（**Push Notifications は入れない**。このアプリの通知は端末内で予約するローカル通知なので、プッシュ通知の設定は要りません）

## 5. App Store 申請の手順

**最初の申請の前に1回だけ（アカウント単位）: EU の「取引業者（trader）」の申告**

App Store Connect の **「ビジネス」→ 契約 → コンプライアンス → Digital Services Act** で、trader status（取引業者かどうか）を申告します。嘘つき村の事件簿の申請で同じアカウントで済ませていれば、もう一度行う必要はありません。

- **EU で配信しない場合でも申告が必要**です。まだ申告していなければ、提出のときに求められます
- 会社として出すなら「trader（取引業者）」を選びます。D-U-N-S に登録した住所と、ここで入力した電話番号・メールアドレスが、EU 27か国の App Store の製品ページに表示されます
- メールと電話に届く確認コードの入力と、会社名・住所を証明する書類（登記簿謄本など）の提出が要ります。確認に数日かかることがあるので、早めに済ませてください
- 住所などを EU のストアに出したくない場合も申告は必要で、その場合は配信国から EU の国々を外すことになります

1. [App Store Connect](https://appstoreconnect.apple.com) →「アプリ」→「＋」→「新規アプリ」
   - プラットフォーム: iOS / 名前: 6章のアプリ名 / プライマリ言語: 日本語 / バンドルID: `work.ltv.dandori` / SKU: `dandori-001`（任意の文字列）
2. Xcode: 上部のデバイスを **Any iOS Device (arm64)** にして **Product → Archive**
3. Organizer が開いたら **Distribute App → App Store Connect** でアップロード（10〜30分ほどで App Store Connect に出てくる）
4. App Store Connect でアプリ情報を入力（6章の下書き・スクリーンショット・プライバシー・年齢制限）
5.「App Review に関する情報」
   - **連絡先（必須）**: 氏名・メールアドレス・電話番号を入れる。審査で質問があったときに Apple が連絡する先で、利用者には表示されません。電話番号は +81 から始まる国際形式（例: `+81 90-1234-5678`）。岩崎さん、または窓口の担当者を入れてください
   - メモ欄に7章の英文を貼る（サインインは不要なので「サインインが必要」はオフ）
6. 価格は「無料」、配信国を選び（EU の国を含めるなら、上の trader の申告が済んでいること）、ビルドを選んで **審査へ提出**

### プライバシー（App Store Connect「App のプライバシー」）

- **「データを収集しません」** を選択してください。
- 理由: アプリは記録をすべて端末内に保存し、外部へ送信しません。アナリティクス・広告・トラッキングはありません。通知は端末内で予約するローカル通知で、プッシュ通知のサーバーは使っていません。
- 補足: 文字の表示のために Google Fonts（Google のサーバー）から書体を読み込みます（ふつうのウェブページの読み込みと同じで、記録や操作の内容は含まれません）。これはプライバシーポリシーにも書いてあります。気になる場合は、書体をアプリ内に同梱する改修を先に行います（清武に相談してください）。
- アプリ内には Apple が求める「プライバシーマニフェスト」（`ios/App/App/PrivacyInfo.xcprivacy`。トラッキングなし・収集データなし、保存機能（UserDefaults）の利用理由）を入れてあります。

## 8. アプリ内容を修正したい場合

アプリ本体は1つ上のフォルダの `index.html` です（画面・段取りエンジン・絵まですべてこの1ファイル）。修正後、このフォルダで:

```bash
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
npm run sync
```

を実行すると iOS プロジェクトに反映されます。そのあと Xcode で Build 番号を1つ上げて、再ビルド → Archive → アップロードしてください。

- 段取りエンジン（`index.html` の `// ==ENGINE START==`〜`// ==ENGINE END==`）を変えたときは、先に `node ../tools/check-engine.mjs ../index.html` を実行し、最後に `PASS` が出ることを確かめる。画面・保存・ネイティブ連携を変えたときは `node ../tools/check-app.mjs ../index.html`
- アイコンを変えるとき: `../icon.svg` を直して `python3 ../tools/make-images.py icons`（アイコンと起動画面の元を作り直す）→ このフォルダで `npm run icons`
- `www/` と `ios/App/App/public/` は `npm run sync` が作るコピーです。ここを直接直しても次の sync で消えます
- 作業が終わったら `rm -rf node_modules ios/App/Pods` で消してください（Dropbox の同期が重くなるため。次は `npm install` → `npm run sync` で戻ります）
- GitHub（`kiyotake1229/dandori-meijin`）に push すると、GitHub Actions の「iOS build check」が、シミュレータ向けと実機向け（署名なし）のビルドが通るかを確かめます
