## 変更内容

### 1. アイコン（`icon.svg` と PNG）

- 図柄: 藍の方眼紙（ダークの青焼きの色 `#173462` 系、32px・128px ごとの罫線）に、付箋の色の作業の帯を3本（手 `#FFE15A`・コンロ `#FFA08A`・炊飯器 `#A3E2B6`）、工程表のようにずらして並べた。帯の頭に置いた順の番号（カードの番号と同じ紺の丸）、帯が始まる前の待ちは空き時間の斜線、右に完成の線（橙 `#FF8C4E`）とチェックの旗、下に時間の目盛り。ホーム左上のロゴと同じ形
- 付箋は少し傾け、上にのりの帯（少し濃い）と影を付けた
- 角丸なし（OS が付ける）。四隅まで紙面で塗り、透明な部分は無い
- 帯・旗・目盛りは中心から半径 400px 以内（1024px のとき）。Android の丸いマスクの安全域（半径 409.6px）に収まるので、同じ PNG を `any` と `maskable` の両方に使う
- 番号は文字ではなく線で描いた（書体が無い環境でも同じ絵になる。アイコンの書き出しに通信が要らない）
- 180px・192px・丸いマスク・60px・40px に縮めて、帯と旗が見分けられることを目で確かめた

書き出し（このフォルダで実行。Google Chrome・Python 3 と Pillow。OGP は書体を読むための通信も要る）:

```bash
python3 tools/make-images.py          # アイコンと OGP の両方
python3 tools/make-images.py icons    # アイコンだけ
python3 tools/make-images.py ogp      # OGP 画像だけ
```

- 嘘つき村の `tools/make-images.py` と同じ形。Chrome の画面なしモードで 1024px を1回だけ描き、Pillow で 512 / 192 / 180 に縮める。すべて透明なし（RGB）
- Chrome を待つのは最長90秒（`TIMEOUT`）。「bytes written to file」が出たら Chrome を終わらせる。終わらなければ terminate → kill（どちらも timeout 付き）で止め、失敗として終わる
- 検査: 下地の赤紫（描けなかった印）が出ていないか、安全域の中に付箋の3色と旗の白があるか、四隅が藍か。OGP は書体が読めないと赤紫になり、書き出さずに止まる
- 作業用のファイル（Chrome のプロファイル・描く HTML）は一時フォルダに作って消す

### 6. `index.html` に足したもの

#### `<head>`

- 説明文を更新。theme-color（ライト `#EDF2F4`・ダーク `#0A2240`、`media` 付き。前からあった）、`mobile-web-app-capable`・`apple-mobile-web-app-capable`・`apple-mobile-web-app-title`（段取り名人）・`apple-mobile-web-app-status-bar-style`（`default`。`black-translucent` だとライトの紙面で時計の文字が読めないため。嘘つき村と同じ）、`canonical`、OGP・Twitter カード（画像は絶対 URL）
- **manifest と apple-touch-icon は、`<head>` の小さなスクリプトが置く。iframe・sandbox（Claude Artifact）の中では置かない**（嘘つき村は `<link>` を直接書いているが、ここだけ変えた）。理由: Artifact を真似た iframe（srcdoc・CSP 付き）で、Chrome が apple-touch-icon を読みに行き、CSP に止められてコンソールにエラーが出た。Artifact の中ではホーム画面に追加できないので、置かなくても困らない。直接開いたとき（GitHub Pages・ローカル・iOS アプリ）は、読み込みの途中で `<link>` を足すので、manifest もアイコンも読まれる（Chrome の画面なしモードで `Page.getAppManifest` が manifest を読めることを確かめた）

#### ネイティブ連携（Capacitor の iOS アプリのときだけ。Web ではどれも何もしない）

- 判定（`// ==NATIVE START==`〜`END`）: `NATIVE`（`window.Capacitor.isNativePlatform()` が true。判定が例外でも false）、`CAP`（`window.Capacitor.Plugins`）、`plug(名前)`（ネイティブでプラグインがあるときだけそのオブジェクト）、`quiet`（Promise の失敗を外に出さない）、`FRAMED`（iframe・origin の無い sandbox・親を読めない iframe）。プラグインは import せず `window.Capacitor.Plugins` から使う
- 使うプラグインとメソッド

| プラグイン（npm） | メソッド | 使う場面 |
|---|---|---|
| Haptics（`@capacitor/haptics`） | `impact({ style: 'LIGHT' })` / `impact({ style: 'MEDIUM' })` / `notification({ type: 'SUCCESS' })` / `notification({ type: 'WARNING' })` | カードを置く・設定の切り替え / 完成 / 最短で完成 / まだ置けないカードを押した。設定の「振動」OFF で止める |
| Preferences（`@capacitor/preferences`） | `get({ key })` / `set({ key, value })` | 記録の二重保存。キーは localStorage と同じ `dandori.v1` |
| LocalNotifications（`@capacitor/local-notifications`） | `getPending()` / `cancel({ notifications })` / `checkPermissions()` / `requestPermissions()` / `schedule({ notifications })` / `addListener('localNotificationActionPerformed')` | 毎朝の通知・通知を押して開く |
| App（`@capacitor/app`） | `addListener('appStateChange')` | 裏に回ったら止めて保存、戻ったら再開・通知の予約し直し・状態バーの当て直し |
| StatusBar（`@capacitor/status-bar`） | `setStyle({ style })` | 状態バーの文字色を画面の色に合わせる（ダーク = `DARK`、ライト = `LIGHT`、自動 = `DEFAULT`）。起動時・0.9秒後・色を変えたとき・端末の外観が変わったとき・アプリに戻ったとき |

- **記録の二重保存**（`// ==STORE START==` の中）: 保存のたびに localStorage と Preferences に同じ JSON を書く（`persist` → `prefsSave`）。起動時は `nativeRestore` で Preferences を読み、次の決まりでそろえる
  - localStorage が空・壊れている・**開いたときに空だった**（`blankAtStart`）、または Preferences のほうが新しい（`t` が大きい）→ Preferences から戻す（localStorage にも書き戻す）
  - localStorage のほうが新しい・Preferences が空 → Preferences に書いて追いつかせる
  - 新しい版のアプリが保存した記録（v が2以上）は、どちらにあっても読まず、上書きもしない
  - **戻す順**: Preferences を読み終えるまで（`restoring`）は Preferences に書かず、「記録が空なら既定の形を保存」（`persistIfEmpty`）もしない。起動（`boot`）は読み終えてから（最長1.2秒待つ。遅れたら先に起動し、読み終えたら描き直す）。起動までは画面を押せない。こうしないと、OS が localStorage を消したあとの起動で、空の記録（時刻が新しい）が Preferences の記録を上書きしてしまう
- **毎朝の通知**（設定「毎朝の通知」と「知らせる時刻」。初めは OFF・7:00）: 題「今日の段取りが届きました」、本文「No.3「肉じゃがの夕ごはん」（★★☆・台所）。全部が終わる時刻を最短にしよう。」。今日から28日分を1日ずつ予約（時刻を過ぎた分は入れない）。通知の番号は `810000 + No.`。予約し直すときは、この番号の範囲の予約だけを取り消してから入れ直す（起動・アプリに戻ったとき・設定を変えたとき）。**許可を求めるのは ON にしたときだけ**（断られたら OFF のまま、設定の行に「通知が許可されていません。iPhone の「設定」→「通知」→「段取り名人」で許可できます。」）。予約し直しでは許可の状態を確かめるだけ。通知を押すと今日の段取りを開く（起動前に届いたものは起動のあと）。**Web では設定の行を出さない**（LocalNotifications があるときだけ）
- **裏に回ったとき**（`pauseAll` / `resumeAll`。ブラウザは `visibilitychange`、iOS アプリは App の `appStateChange` でも）: 並べている途中を保存し、段取りの再生（結果の［最短の段取りを見る］）を止めて最後の形にし、完成の演出のタイマーを止め、音（AudioContext）を止める。戻ったら日付を確かめ、完成の演出の途中だったら結果へ進む
- 設定: iOS アプリでは振動の説明「カードを置く・完成・最短で軽く震える」、保存先「この端末のアプリの中」。いちばん下に「サポート・プライバシーポリシー」のリンク（`https://kiyotake1229.github.io/dandori-meijin/support.html`、別のタブ）。スイッチを押したあとも焦点をスイッチに残すようにした

#### Service Worker の登録（`registerSW`）

`boot()` の最後で呼ぶ。登録しないのは、iOS アプリの中（`NATIVE`）／Claude Artifact のような iframe・sandbox の中（`FRAMED`）／http(s) 以外（file: など）／安全でない接続／Service Worker の無いブラウザ。画面の読み込みが終わってから（`load` のあと）登録し、失敗しても何もしない。

#### そのほか

- 結果のコピー文の最後に公開 URL（`SITE_URL` = `https://kiyotake1229.github.io/dandori-meijin/`）を入れた。コピーできない環境の欄は6行にした
- download リンク: このアプリには無い（嘘つき村の「画像を保存」にあたるものが無い）。`check-app` で、出すなら `NATIVE`・`FRAMED` で外すことを確かめる

### 8. `tools/check-app.mjs` に足した検査（82 → 126項目）

偽の `window.Capacitor`（`isNativePlatform: () => true` と各プラグインのダミー）・偽の DOM・偽の Service Worker の環境で、index.html から取り出した関数を動かして確かめる。

- 判定: Web（Capacitor が無い・Web 版の Capacitor・判定が例外）では `NATIVE` が false で `plug` は何も返さない／iOS アプリではプラグインを返す／`FRAMED` は iframe・sandbox・親を読めない iframe で true
- Service Worker の登録: https・ローカルでは登録（読み込みの途中なら load のあと）／iOS アプリ・iframe・sandbox・file:・安全でない接続では登録しない／Service Worker の無いブラウザでも例外なし
- 二重の保存: 保存のたびに Preferences にも同じ JSON／localStorage が空なら戻す／新しいほうにそろえる（両方向）／Preferences が空なら書く／**読み終える前は「空なら保存」も Preferences への書き込みもしない／開いたとき空なら、待つ間に書かれた新しい空の記録より Preferences を優先**／新しい版の記録は読まず書かない／読めなくても遊べる／Web では何もしない／起動の順（ソース）

## 既知の注意点

- 同じドメイン（kiyotake1229.github.io）のほかのアプリの中には、activate で「自分以外のキャッシュを全部」消すものがある（嘘つき村の #0013）。消された直後に通信なしで開くと開けない。一度つながった状態で開けば `refill` で戻る
- 日本語の書体は文字のまとまりごとのファイルに分かれていて、表示した文字のファイルだけを読む。オフラインで初めて出る文字は、端末の書体で出ることがある
- ローカル（127.0.0.1）でも Service Worker は登録される。ローカルで確かめたあとは登録を解除しておく
- `support.html` の「iOS アプリ版は準備中です」は、App Store に出たら直す
- 嘘つき村の `index.html` も manifest・apple-touch-icon を `<link>` で直接書いているので、Artifact の中で同じエラーが出ている可能性がある（嘘つき村は変えていない）
- `check-engine` の時間の検査（「性能: 最大100ms以下」「遠い先の dailyConfig・daily も軽い（初回 100ms 以下）」）は、マシンが混んでいると 100ms を超えて FAIL する（この作業の前の index.html でも1回 FAIL し、次は PASS した。ほかの作業でマシンが混んでいた時間（load average 5 前後）は最大 119〜214ms で FAIL、空いてから測り直して 98.8ms で PASS）。ふだんでも最大は 100ms ぎりぎりなので、FAIL したら、回帰ハッシュが PASS しているかを見たうえで、マシンが空いているときに測り直す
