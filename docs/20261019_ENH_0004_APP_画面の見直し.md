## 概要

#0003 のエンジンに画面を合わせ、あわせて「置く前に、いつ始まるかが分からない」という監査の指摘（後から置いた作業が前の空きに入らない決まりが理不尽に感じられる）に対応した。カードに「いま置くと◯〜◯分」を出し、工程表の動きを足した。
この文書は、反映したときに書けていなかった分をあとから記録したもの。予想のつまみ・「いい読み」の幅などは #0005 でさらに直している。

## 対象ファイル

- `tools/check-app.mjs`

## 変更内容

### 置く前の見込み（監査の指摘14）

- 置けるカードに「いま置くと **0〜4** 分」を出す（`forecastOf`）。道具の順番待ちで遅れるときは「手の順番待ち」と添え、入れそうに見える前の空きがあれば「0〜14分の空きには入らない」と書く
- PC でカードに触れた（マウス・キーボード）ときは、置いたら入る場所を工程表に点線で出す（`showGhost`。指で押すときは出さない）
- 置いたカードは付箋が工程表へ移った跡（点線の枠）だけが残る。前提待ちのカードは斜線で押せないことを示す
- 完成の数字は前の値から数え上げ、完成の線と旗は前の位置から滑らせる（`countTo`・`slideFin`）。完成したら時刻の針が0から完成まで走ってから判を押す。動きを控える設定ではすぐ変える
- 下の固定バーの真ん中に、完成の時刻と置いた枚数を出す（カードを見ているあいだも分かる）

### エンジン VERSION 3 の API に合わせた所

- 予想のスライダーの範囲を `stats.guessLo`〜`guessHi` にした。つまみを動かすまでは数字を「？」にし、［予想して始める］を押せなくした（真ん中のまま押すだけで当たる問題があったため）。はじめての段取りでは予想を出さない。※#0005 で、つまみの最初の位置を下限にし、触れた値で選べるように直した
- 結果の★は `Engine.grade(pz, ms)`、記録帳は保存した最短から `Engine.near(best)` で同じ決まりを使う。「おしい！」の境目は `solution.near`。遊び方のルール5も「遅れが最短の1割まで」に書き直した
- はじめての段取りの案内は、エンジンの lesson（intro・tip・on・hint・done）だけを使う。置いている途中は explain の文（答えの作業名を言う）を出さず、答えは結果の「ここがコツ」で見せる
- 結果の工程表で印を付ける作業は `explain` の `diffTask`。最短の段取りは「あなたの頭を引き継いだ最短の一例」を1枚ずつ再生し、並べ方の表に分かれた所を赤で示す
- 遊び方の曜日の表は `Engine.WEEK` から、ホーム・練習の「作業4〜5個」などは `Engine.SHAPE` から作る（決まりが変わってもずれない）
- はじめて現場の日を迎えたとき（現場の日替わりをまだ完成させていない）、ホームに「今日は現場の段取り。単位は日」と一言出す
- 時刻の表記を「0分から」にそろえた（カードの見込み・工程表の目盛り・ここがコツ）

## 確認

- `node tools/check-app.mjs index.html` → **PASS 69項目**（統合のとき。60から9項目増）。足した検査: 予想の範囲（72問と日替わり14日）・つまみを動かす前の状態・保存していた予想を範囲に収める・記録帳の★と Engine.grade の一致・結果の★と「おしい」・案内が lesson.on/hint を使う・lesson の5つの文・曜日の表が Engine.WEEK から作られる・作業の数が SHAPE から作られる。入れ替え直後の写し（新エンジン＋古い画面）では、このうち6項目が FAIL することを確かめた
- アプリ内の Browser（スマホ幅375・ミュートを流してから操作）で、初回 → はじめての段取り3話 → 今日の段取り No.1（予想・最短・再生）→ 練習★3 台所・現場 → 記録帳・遊び方・設定（ダーク）を確かめた。コンソールのエラー0、横スクロールなし。画面なしの Chrome で 320・375・1280 幅、ライト・ダークも撮って確かめた
