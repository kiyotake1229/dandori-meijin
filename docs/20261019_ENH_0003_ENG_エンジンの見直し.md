この文書は、反映したときに書けていなかった分をあとから記録したもの。VERSION 3 の一部（予想の範囲・★の難しさ）は、#0005 でさらに直している。

### 問題の作り方（全部の問題が変わる）

| 項目 | VERSION 2 | VERSION 3 |

| ★2・★3 の「よく知られたコツでは届かない」 | 同点（所要時間が同じなど）は、上のカードから選んだ1通りだけを見ていた。同点の選び方しだいで届く問題が約2割あった | 同点の選び方を全部たどり（`trickRange`）、どの選び方でも届かないことを条件にした。★3 は「後に続く流れが長い順（cp）」でも届かないことを必須に、「いちばん早く始められる順（est）」は目安（softTricks）にした |

### 文の作り方・API（問題は変わらない）

- 「ここがコツ」（`explain`）
  - 勧める作業は、あなたの順番の1枚だけを動かして本当に完成が早まるもの（`bestMove`）。あなたの段取りでも同じ時刻に始めていた作業は勧めない
  - 1文目は理由（どの作業が、どの道具を、どの作業にふさがれて何分遅れたか）、2文目は直し方。後回しにすべき作業は「〇〇は後回し。職人は2日待って△△に入れば…」と書く
  - 「完成を決める流れ」は、前提のつながりを「→」、同じ道具が空くのを待つつながりを「→（〇〇が空いてから）」と書き分ける。道具の合計で最短が決まる問題は「〇〇の作業は合計◯分。最短は、〇〇を1分も休ませない段取り。」
  - 最短に届いたときの2文目は、上から順の落とし穴・待ち時間の使い方・道具を休ませなかったこと、から選ぶ（#0005 で、落とし穴の文を本当に決め手になる一手だけに直した）
  - 時刻は 0 も「0分から」と書く（カードの「いま置くと」・工程表の目盛りにそろえる）
  - 無効な番号は `schedule` と同じく飛ばして続ける（結果の数字と解説が食い違わない）
- `generate` の seed が NaN・Infinity なら文字列にして使う（保存して読み戻しても同じ問題になる）
- 日替わりの献立の割り当ては No.1 から順に決めるので、No. が大きいほど重い。約30年（No.10958）より先は日付の hash で選ぶ（9999年の時計で8秒固まっていた）
- 公開する値を足した: `Engine.WEEK`（曜日の表）、`Engine.SHAPE`（★の形）、`Engine.grade`・`Engine.near`、問題の `stats.guessLo`・`guessHi`・`lb`・`smart`、`tasks[i].hot`、`solution.near`
