# エンジン検査の性能の合否の線

- 管理番号: #0009
- 種類: FIX（軽微な修正）
- 対象: ENG（`tools/check-engine.mjs` の生成時間の検査。エンジンそのものは変えていない）
- 作成日: 2026-10-20
- 関連: #0002（性能の上限を 300ms → 100ms に下げた）、#0006（「既知の注意点」に、マシンが混んでいると 100ms を超えて FAIL すると書いた）、#0008（このときの公開）

## 概要

`check-engine` の「性能: 最大100ms以下」と「遠い先（9999-12-31）の dailyConfig・daily も軽い（初回 100ms 以下）」は、マシンが混んでいると 100ms を超えて FAIL していた（空いていれば最大 98.8ms で、ふだんでもぎりぎり）。エンジンの問題ではなく測る環境の揺れで FAIL するので、**合否の線を仕様の目標（最大 300ms 以下）に戻し、100ms は目安として「超えた数と最大」を表示するだけ**にした。あわせて、結果を読むためにマシンの混み具合（load average）とかかった時間を表示する。
遅かった回を測り直して隠す形にはしていない（測り直しの決まりは #0002 のまま）。エンジンは変えていないので、**問題は変わらない（VERSION 4 のまま）**。

## 対象ファイル

- `tools/check-engine.mjs`

## 変更内容

| 項目 | 前 | 後 |
|---|---|---|
| `PERF` | `{ avg: 50, max: 100 }` | `{ avg: 50, max: 300, aim: 100 }` |
| 「性能: 最大…ms以下」 | 最大 100ms 以下で PASS | 最大 300ms 以下で PASS（名前は「性能: 最大300ms以下（仕様の目標。目安 100ms は表示だけ）」） |
| 「遠い先（9999-12-31）の dailyConfig・daily も軽い」 | 初回 100ms 以下 | 初回 300ms 以下（#0003 の前は8秒かかっていた。この戻りを見つけるには 300ms で足りる） |
| 目安の表示（新しい行） | なし | 「目安（100ms）: 超えた生成 N/1085問（最大 …ms）。マシンが混んでいないときに測り直して、続くようならエンジンを見直す」（遠い先の日付が目安を超えたときはそれも） |
| 混み具合の表示（新しい行） | なし | 「マシンの混み具合: load average 始め … → 終わり …（CPU …）。かかった時間 …秒（空いていれば約30秒）…」 |

- 測り直しの決まり（100ms を超えた回は新しいエンジンで3回測り直して短いほう。測り直す前の最大も表示）は #0002 のまま変えていない
- 「性能: 平均50ms以下」「10年先の dailyConfig も軽い（初回 50ms 以下）」も変えていない
- 300ms は #0002 の前に使っていた上限と同じ。画面は「読み込み中」を出してから次のフレームで問題を作るので、スマホ（Node の4〜6倍遅い見込み）で 0.5 秒前後までなら固まって見えない。目安の 100ms はそのまま表示に残し、超えた数が増えてきたらエンジンを見直す

## 確認

この作業のあいだ、マシンはずっと混んでいた（load average 6〜7.6、CPU 10。ほかの作業が動いていた）。空いていれば約30秒の検査が、約2分かかった。

| 回 | 結果 | 生成の最大（測り直す前） | 目安の 100ms を超えた数 | かかった時間・混み具合 |
|---|---|---|---|---|
| 1 | PASS 110項目 | 261.8ms（261.8ms） | 18/1085問 | 130.7秒・load average 6.5 前後 |
| 2 | **FAIL**（性能: 最大 300ms 以下だけ） | 406.3ms（432.8ms） | 27/1085問 | 115.9秒・load average 7.6 |
| 3 | PASS 110項目（混み具合の表示を足したあと） | 221.9ms（221.9ms） | 12/1085問 | 109.0秒・load average 6.3 |

- どの回も、回帰ハッシュ（日替わり365日・練習120問・はじめての段取りと例題）・良い問題の条件・★の難しさなど、性能以外はすべて PASS。問題は変わっていない
- 2回目のように、マシンがとても混んでいる（混んでいると Apple シリコンの効率コアで動くことがあり、時間が数倍になる）と 300ms でも FAIL する。このときは、回帰が PASS していることを見たうえで、空いているときに測り直す（#0006 の空いているときの最大は 98.8ms）。新しい行の「マシンの混み具合」と「かかった時間（空いていれば約30秒）」で、混んでいたかが分かる
- `node --check tools/check-engine.mjs`: 問題なし。`node tools/check-app.mjs index.html`: PASS 126項目
